# Cinema Booking API

REST API сервісу бронювання місць у кінотеатрі на NestJS: фільми, зали, сеанси й бронювання.
Бази даних немає — усі дані зберігаються в пам'яті сервісів і зникають після перезапуску.

## Вимоги

- Node.js 22 LTS (або новіший)
- npm

## Запуск

```bash
# встановлення залежностей
npm install

# змінні оточення
cp .env.example .env

# запуск у dev-режимі (з перезапуском при змінах)
npm run start:dev
```

Сервер: http://localhost:3000, документація Swagger: http://localhost:3000/docs

### Змінні оточення (`.env`)

| Змінна | Опис | Приклад |
|---|---|---|
| `PORT` | Порт HTTP-сервера | `3000` |

## Перевірка

- `requests.http` — усі маршрути й усі описані помилки. Відкрити у VS Code з розширенням
  [REST Client](https://marketplace.visualstudio.com/items?itemName=humao.rest-client) і виконувати запити
  згори вниз на щойно запущеному сервері; id підставляються автоматично зі змінних.
- `npm run test:e2e` — автоматичні e2e-тести тих самих сценаріїв.

## Маршрути

| Маршрут | Успіх | Помилки |
|---|---|---|
| `POST /films` | 201 | 400 |
| `GET /films` | 200 | — |
| `GET /films/:id` | 200 | 404 |
| `PATCH /films/:id` | 200 | 400, 404 |
| `DELETE /films/:id` | 204 | 404, 409 (є сеанси) |
| `POST /halls` | 201 | 400, 409 (назва зайнята) |
| `GET /halls` | 200 | — |
| `GET /halls/:id` | 200 + `seats` | 404 |
| `DELETE /halls/:id` | 204 | 404, 409 (є сеанси) |
| `POST /showings` | 201 | 400 (фільм/зал не існує, дата не ISO 8601 або в минулому, ціна) |
| `GET /showings?filmId=&date=YYYY-MM-DD` | 200 | 400 |
| `GET /showings/:id` | 200 | 404 |
| `GET /showings/:id/seats` | 200 | 404 |
| `POST /showings/:id/bookings` | 201 | 400, 404, 409 (місце зайняте) |
| `GET /showings/:id/bookings` | 200 | 404 |
| `GET /bookings` | 200 | — |
| `DELETE /bookings/:id` | 204 | 404 |

Параметр `:id` у шляху має бути UUID, інакше — 400.

## Рішення

- **Ціни** зберігаються в копійках (цілі числа): `12500` = 125 грн. `totalPrice` = ціна сеансу × кількість місць.
- **Місця** не зберігаються: перелік обчислюється з `rows × seatsPerRow`, місце — пара `row` + `seat` (нумерація з 1).
- **Фільтр `date`** відбирає сеанси, що починаються в цю добу за UTC. `startsAt` зберігається й повертається в UTC.
- **Розклад** відсортований за `startsAt` за зростанням, при однаковому часі — за `id`. Кожен сеанс містить
  `film: { id, title }` і `hall: { id, name }`.
- **Назва залу** унікальна без урахування регістру й пробілів на краях.
- **Бронювання атомарне**: спершу перевіряються всі місця, і лише потім створюється запис — якщо хоча б одне
  місце зайняте (409) або не існує в залі (400), не бронюється жодне.
- **Розподіл перевірок**: DTO з `class-validator` перевіряють форму запиту (наявність, тип, діапазон, формат,
  унікальність місць у масиві); сервіси — доменні правила (існування фільму/залу, межі залу, зайнятість місць,
  залежні сеанси при видаленні). `ValidationPipe` глобальний з `whitelist: true` — зайві поля відкидаються.

## Структура

```
src/
  films/      FilmsModule    — фільми
  halls/      HallsModule    — зали та обчислення місць
  showings/   ShowingsModule — сеанси, розклад, карта місць і бронювання
  setup-app.ts               — глобальний ValidationPipe і Swagger
```

Модулі звертаються один до одного лише через експортовані сервіси. Бронювання розміщено в модулі сеансів,
бо карта місць сеансу і бронювання залежать одне від одного.

`films` і `halls` пов'язані з `showings` у дві сторони: сеанс перевіряє існування фільму й залу, а видалення
фільму чи залу перевіряє, чи немає в них сеансів. Цю зустрічну залежність розв'язано через `forwardRef`.
